Payment API Concept Notes

Design secure payment flows with state machines, idempotency, and webhook verification. ← Back · Practice

Core model

  • Client starts payment intent/session
  • Provider confirms or fails transaction
  • Webhook updates final status
  • System reconciles and audits outcome

Must-have controls

  • Idempotency key for create/confirm calls
  • Webhook signature verification
  • Immutable payment status history
  • Reconciliation job for missed callbacks
